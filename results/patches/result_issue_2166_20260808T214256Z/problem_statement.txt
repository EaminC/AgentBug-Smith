# Issue #2166: [Bug]: _agent.py -Duplicate ToolResultStartEvent emitted for external tool on interruption

### Prerequisites

- [x] I have searched the existing [issues](https://github.com/agentscope-ai/agentscope/issues) and [discussions](https://github.com/agentscope-ai/agentscope/discussions), and this is not a duplicate.
- [x] This is a bug, not a usage question. (For questions, please use [Discussions](https://github.com/agentscope-ai/agentscope/discussions/new?category=general) instead.)

### Background / Description

When an external tool call is interrupted while in SUBMITTED state, _close_unfinished_tool_calls emits a second ToolResultStartEvent for the same tool call. The first START was already emitted by _execute_tool_call when transitioning to ALLOWED.

Root cause: _close_unfinished_tool_calls (line 640) only excludes ALLOWED from re-emitting START, but for external tools, the active lifecycle is ALLOWED → SUBMITTED — both states have START already emitted.

Expected: 1 START event per tool call.
Actual: 2 START events when an external tool in SUBMITTED state is interrupted.

### Error Messages

```shell
No exception. The bug is observable in the event stream
```

### Steps to Reproduce

1.Configure an agent with any is_external_tool = True tool.
2.Call agent.reply() — the tool enters SUBMITTED state, waiting for the external system.
3.Send a UserInterruptEvent to interrupt the agent before the external system returns.
4.Count ToolResultStartEvent events in the stream for the same tool_call_id.

Expected: 1.
Actual: 2.
