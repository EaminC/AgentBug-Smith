# Issue #1067: [BUG] Decorator functions send the entire doc string as the description of the tool

### Checks

- [x] I have updated to the lastest minor and patch version of Strands
- [x] I have checked the documentation and this is not expected behavior
- [x] I have searched [./issues](./issues?q=) and there are no duplicates of my issue

### Strands Version

latest

### Python Version

3.11

### Operating System

macos

### Installation Method

git clone

### Steps to Reproduce

```python
import json
from typing import Union
from strands import tool


@tool
def sleep(seconds: Union[int, float]) -> str:
    """
    Pause execution for the specified number of seconds.

    This tool pauses the execution flow for the given number of seconds.
    It can be interrupted with SIGINT (Ctrl+C).

    Args:
        seconds (Union[int, float]): Number of seconds to sleep.
            Must be a positive number greater than 0 and less than or equal to
            the maximum allowed value (default: 300 seconds, configurable via
            MAX_SLEEP_SECONDS environment variable).

    Returns:
        str: A message indicating the sleep completed or was interrupted.

    Raises:
        ValueError: If seconds is not positive, exceeds the maximum allowed value,
                   or is not a number.

    Examples:
        >>> sleep(5)  # Sleeps for 5 seconds
        'Started sleep at 2025-05-30 11:30:00, slept for 5.0 seconds'

        >>> sleep(0.5)  # Sleeps for half a second
        'Started sleep at 2025-05-30 11:30:00, slept for 0.5 seconds'
    """
    pass

print(json.dumps(sleep.tool_spec, indent=2))
```

### Expected Behavior

In the [docs for tools](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/tools/python-tools/), there's a paragraph that says:

> The decorator extracts information from your function's docstring to create the tool specification. The first paragraph becomes the tool's description, and the "Args" section provides parameter descriptions. These are combined with the function's type hints to create a complete tool specification.

So the tool description in the tool spec should exclude argument descriptions and perhaps only include the first paragraph(s).

Or the docs should be updated.

### Actual Behavior

The entire doc string is passed as the description:
