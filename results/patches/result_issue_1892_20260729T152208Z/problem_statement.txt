# Issue #1892: [Bug]: AnthropicChatFormatter splits parallel tool_results into multiple user messages -> 400 on DeepSeek

### Prerequisites

- [x] I have searched the existing [issues](https://github.com/agentscope-ai/agentscope/issues) and [discussions](https://github.com/agentscope-ai/agentscope/discussions), and this is not a duplicate.
- [x] This is a bug, not a usage question. (For questions, please use [Discussions](https://github.com/agentscope-ai/agentscope/discussions/new?category=general) instead.)

### Background / Description

Using agentscope with DeepSeek (Anthropic-compatible endpoint). When the model returns several tool_use blocks in one reply, the next call fails with 400.

AnthropicChatFormatter splits the tool_results into multiple user messages, but they should be in ONE user message right after the assistant message. DeepSeek checks this strictly and rejects it. Anthropic/GLM endpoints are lenient so it stays hidden.

Root cause: in agentscope/formatter/_anthropic_formatter.py, the ToolResultBlock branch flushes whenever content_blocks is non-empty, so each tool_result becomes its own user message. One-line fix works (see Steps to Reproduce).

### Error Messages

```shell
anthropic.BadRequestError: 400 - {
  'error': {
    'message': "messages.7:`tool_use` ids were found without `tool_result` blocks immediately after: call_00_..., call_01_..., call_02_..., call_04_.... Each `tool_use` block must have a corresponding `tool_result` block in the next message.",
    'type': 'invalid_request_error'
  }
}

messages.7 = assistant turn with 5 tool_use blocks. The 5 tool_results ran fine but were sent as separate user messages.
```

### Steps to Reproduce

Triggers when the model returns 2+ tool_use blocks in one reply. agentscope stores them + their tool_results in the same AssistantMsg.content:

[text, tool_use x3, tool_result x3]

Run the formatter -> you get 1 assistant + 3 user messages (one per tool_result), instead of 1 assistant + 1 user. DeepSeek rejects it.

Setting tools to sequential (is_concurrency_safe=False) does NOT help — _save_to_context still merges all tool_results into one assistant message.

Suggested fix in agentscope/formatter/_anthropic_formatter.py, ToolResultBlock branch:

  - if content_blocks:
  + if content_blocks and not has_tool_result:

First tool_result still flushes the assistant content (unchanged); following tool_results then merge into one user message. Single-tool output identical before/after.

### Environment

- AgentScope Version: 2.0.0
- Python Version: 3.11
- OS: macOS (darwin, arm64)
- Model: DeepSeek deepseek-v4-pro via Anthropic-compatible endpoint
