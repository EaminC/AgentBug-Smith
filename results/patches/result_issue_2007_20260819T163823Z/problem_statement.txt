# Issue #2007: [BUG]  Ollama provider has swapped input/output token counts

### Checks

- [x] I have updated to the lastest minor and patch version of Strands
- [x] I have checked the documentation and this is not expected behavior
- [x] I have searched [./issues](./issues?q=) and there are no duplicates of my issue

### Strands Version

1.33.0

### Python Version

3.12.4

### Operating System

macOS 15.7.3

### Installation Method

pip

### Steps to Reproduce

1. Use the Ollama model provider with any model
2. Run an agent invocation
3. Inspect the usage metrics (e.g. `agent.event_loop_metrics.accumulated_usage`)

### Expected Behavior

`inputTokens` should reflect the number of tokens in the prompt, and `outputTokens` should reflect the number of tokens generated by the model, consistent with [Ollama's API documentation](https://github.com/ollama/ollama/blob/main/docs/api.md)/ https://docs.ollama.com/api/usage:
- `prompt_eval_count` — "number of tokens in the prompt" (input)
- `eval_count` — "number of tokens in the response" (output)

### Actual Behavior

`inputTokens` and `outputTokens` are swapped. At `src/strands/models/ollama.py:276-277`, `eval_count` (output) is mapped to `inputTokens` and `prompt_eval_count` (input) is mapped to `outputTokens`:

```python
"inputTokens": event["data"].eval_count,        # wrong — this is output
"outputTokens": event["data"].prompt_eval_count, # wrong — this is input
```

`totalTokens` is coincidentally correct since addition is commutative.


### Additional Context

This affects all downstream consumers of per-field token metrics for Ollama users:
- `accumulated_usage["inputTokens"]` and `accumulated_usage["outputTokens"]` are swapped
- OpenTelemetry metrics (`event_loop_input_tokens`, `event_loop_output_tokens`) report swapped values
- Any per-cycle or per-invocation usage inspection shows incorrect input/output breakdown

### Possible Solution

Swap the two mappings at `src/strands/models/ollama.py:276-277`:

```python
"inputTokens": event["data"].prompt_eval_count,
"outputTokens": event["data"].eval_count,
```
